# W34 R0 P3 Backlog-Review Bundles Closeout

## Changes

Moves the logic of the two hand-written `backlog-review` Skill scripts into CLI source next to the backlog presentation code, under design OD-1 option A and PRD 51 R-BACKLOG-SKILL-21. `collect-project-lead-context.mjs` now comes from `packages/cli/src/operations/work/backlog/project-lead-context.ts`, and `render-report.mjs` from `packages/cli/src/operations/work/backlog/report-file.ts`. The generated render script takes its renderer from the sibling `report-contract.mjs`, as before. `packages/cli/scripts/build-backlog-presentation.mjs` builds all four Skill scripts with the same esbuild call, gives each a "Generated by ... Do not edit." header, and gains `--render`, `--collector`, and `--all`. It exports `checkPortableBacklogSkillScripts()`, which P4 can reuse in the guard test.

`packages/cli/tests/backlog-review-skill-bundles.test.ts` (14 tests) proves that each file matches a fresh build byte for byte, that a one-byte change, a missing file, or an extra hand-written file fails, and that each bundle runs from a Skill copy with no `node_modules`. A before and after run of the old and new scripts on 124 cases, including all 85 work records in this repository, gave the same exit codes, output, and HTML bytes. No snapshot code changed, and no bundle reads `snapshot.ts`.

The installed dogfood copy (T7, A15) waits for the owner, because only the owner's Store records the installed Skill files.
