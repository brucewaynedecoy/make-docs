# Software Factory

Complete the unit of work the owner requested. Stay responsible for scope, judgment, and integration while workers do bounded work. Make Docs supplies the product requirements and backlog; this skill does not replace that planning layer.

## Understand the assignment

Use the request and existing context to identify three separate things: the task, stage, phase, or wave; the authorized actions and stop point; and the selected worker method. Ask only when a missing choice would change the work.

An explicit factory request selects coordination. Default to native subagents when supported and permitted. Follow a selected profile or method instead. Read [work methods](references/work-methods.md) for that method. Read [profiles](references/profiles.md) only when a profile is requested. Profiles do not grant permission or prove live capabilities.

Read the applicable repository instructions, assigned backlog, and governing PRD sections. Use relevant current evidence. Resolve already-settled answers without a new interview. If product planning is missing, identify the precise need and return it to Make Docs. Do not invent a backlog or invoke preflight automatically.

## Run a small loop

1. Select work whose dependencies are satisfied.
2. Assign a bounded part to a worker: goal, source links, owned files or responsibility, exclusions, allowed actions, checks, and return point.
3. Receive the result: actual changes, outcome, checks and observations, remaining work, and questions.
4. Inspect the actual candidate against the assigned outcome and accepted requirements. Return defects for correction.
5. Review corrections, integrate accepted work, and continue through the authorized scope.

Use one writer per shared file. Tell workers they are not alone and must preserve others' edits. Do not create or switch branches or worktrees without explicit user permission. Keep briefs focused; use source links instead of copied transcripts.

The coordinator must judge actual work, not endorse a worker's summary. It can independently review changes it did not build. If it built material parts, use another reviewer for those parts. Give reviewers requirements and the candidate without coaching them toward the builder's conclusions. Add another reviewer only when independence or expertise needs it.

Run the project's required checks. Inspect or use the product when its promised outcome depends on a real interaction. Reuse suitable evidence; repeat a check for a changed candidate, independent proof, or an unresolved concern. Green tests do not prove the right behavior. Do not weaken requirements to make a result pass.

## Keep scope and momentum

Routine choices stay with the agent when they preserve the agreed outcome. Before a material departure, explain the old outcome, new outcome, reason, and combined effect with related changes. Pause affected work until the needed choice and authority are settled. Continue independent authorized work where useful.

Use [Store guidance](references/store.md) when saving or resuming lifecycle progress. Worker status stays in the selected tool's existing records. Do not create a tracker, private state schema, or workflow engine.

Worker completion returns control to you. Continue without asking the user to restart the run. Wait on completion events where possible. Give short updates about outcomes and findings, not polling or state mechanics. Preserve prior permission across internal steps.

Honor owner-set limits. Stop a correction loop when it repeats the same failure without a supported new approach. Report the evidence and smallest next step. Do not dispatch duplicate work after an uncertain handoff; inspect its status first.

## Finish with evidence

Report what was delivered, what was checked and observed, and any remaining limits. Distinguish a reviewed candidate from accepted or committed work. Complete the required closeout inside the authorized scope. Commit, push, publish, or deploy only when that action is authorized. Do not add approval ceremonies for already-authorized work or call a Store receipt product acceptance.

Do not silently activate other skills. When the owner explicitly requests human-experience guidance for this assignment, carry its relevant goals into briefs and review.
