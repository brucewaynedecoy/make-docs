# W18 R9 Playbook and Package Conformance Work

## Purpose

Implement the conformance extension required by [37 Enhance Playbook and Package Conformance](../../prd/37-enhance-playbook-and-package-conformance.md): the expanded support tuple for generated Playbook distributables, the queryable tuple registry under `docs/assets/conformance/` with `provisional`/`implementation-validated`/`conformance-validated` statuses derived from run verdicts, the install-discover-invoke-uninstall evidence bar, the required Codex-first first-pass scenarios with honest `blocked` reporting, the three-layer test separation with the internal-tests-are-not-evidence rule, the D9 meta-verification checks including the shipped-artifact exclusion check, and support-claim governance. The source chain is [the design](../../designs/2026-07-01-playbook-and-package-conformance.md), [the W18 R9 plan](../../plans/2026-07-01-w18-r9-playbook-and-package-conformance/00-overview.md), and PRD 37, with [PRD 20](../../prd/20-revise-agent-harness-model-conformance-lab.md), [PRD 33](../../prd/33-enhance-playbook-packaging-and-harness-adapter-registry.md), [PRD 36](../../prd/36-revise-playbook-packaging-compiler-and-harness-adapters.md), [PRD 34](../../prd/34-revise-playbook-contract-and-model.md), [PRD 35](../../prd/35-revise-run-playbook-state-machine.md), [PRD 19](../../prd/19-revise-template-package-dogfood-source-of-truth-contract.md), [PRD 10](../../prd/10-packaging-validation-and-release-reference.md), and — since the W18 R12 remediation round this wave was resequenced behind — [PRD 40](../../prd/40-revise-playbook-authoring-contract-v2.md) and [PRD 41](../../prd/41-revise-cli-human-experience-and-package-grammar.md) as still-constraining baselines.

## Usage Notes

- Read phases in order; they are dependency-ordered and later phases consume earlier deliverables.
- This lineage extends, never redefines: the lab's verdicts, safety modes, evidence classes, storage boundaries, run-record fields, and model-agnostic scenario protocol stay owned by [PRD 20](../../prd/20-revise-agent-harness-model-conformance-lab.md); the packaging compiler, harness adapters, and capability model stay owned by [PRD 36](../../prd/36-revise-playbook-packaging-compiler-and-harness-adapters.md); the Playbook model stays owned by [PRD 34](../../prd/34-revise-playbook-contract-and-model.md) as revised by the clean-break v2 authoring contract in [PRD 40](../../prd/40-revise-playbook-authoring-contract-v2.md); the run-state machine stays owned by [PRD 35](../../prd/35-revise-run-playbook-state-machine.md); and non-packaging scenario families (install, audit, backup, skills) stay owned by the lab design (R-SCOPE-1).
- Cross-design sequencing: this work is sequenced last among the core Playbook-architecture lineages — it verifies the W18 R8 distributables as the artifacts under test, executes workflow-driving scenarios via the W18 R7 runner, and consumes the Playbook model (the W18 R6 lineage as revised by the W18 R12 v2 contract) unchanged.
- W18 R12 reconciliation (2026-07-03, register item [R-026](../../prd/03-open-questions-and-risk-register.md); PRD 41 R-SEQ-2): this backlog was authored before the W18 R12 remediation round landed and now binds to the remediated surfaces. Every Playbook fixture or scenario input uses the v2 authoring contract from [PRD 40](../../prd/40-revise-playbook-authoring-contract-v2.md) — the fenced YAML `dependencies` block with the optional `probe` field, the `schema`/`workflowSchema` frontmatter keys, the simplified heading spine, and the `make-docs.playbook.v2` identifier; no v1 form (dependency table, `schemaVersion`/`workflowSchemaVersion` keys, v1 heading spellings, v1 schema id) parses. Generated dependency checks probe each entry's resolved `probe` (the declared value or the `id` default), never `source` prose, so dependency-check scenario expectations bind to probe-based checks. Scenario scripts spell packaging intent per [PRD 41](../../prd/41-revise-cli-human-experience-and-package-grammar.md): `run package plan` (with `--output`), `preview`, `write` (the `--write` flag is retired), and `ship` where a single-entry flow is exercised. Any scenario transcript that consumes CLI output pins `--json` (or runs non-TTY), because a TTY defaults to the human render layer — conformance evidence must be byte-stable machine output, never rendered text.
- Post-wave relocation (2026-07-06, register item [D-022](../../prd/03-open-questions-and-risk-register.md); [PRD 42](../../prd/42-revise-conformance-asset-home-relocation.md)): after this wave completed, the conformance asset family relocated from `docs/assets/conformance/` — a path the `docs/assets/` router never admitted — to the repo-root maintainer directory `conformance/`.
