# Phase 3: Backlog-Review Bundles

## Purpose

Apply design decision OD-1 option A to the `backlog-review` Skill. Its logic gets one home in CLI source, and the portable no-CLI path stays. This phase depends only on the PRD pass and can run beside P1 and P2.

## Overview

`collect-project-lead-context.mjs` and `render-report.mjs` are hand-written today. This phase moves their logic into CLI source and builds them as generated bundles, as the other two files in `packages/skills/backlog-review/scripts/` already are. A test proves that each file matches a fresh build byte for byte.

## Human Experience Outcome

- Impact and governing promise or preserved boundary: `none` for people who use the Skill. The collector and the report keep the same behavior under [PRD 51](../../prd/51-backlog-review-and-reporting.md) R-BACKLOG-SKILL-21: the same source order, bounded excerpts, repository-relative paths, and content hashes. They still run with Node built-ins only.
- Intended human outcome: unchanged. The project lead sees the same report and context as before.
- Human-facing surface or indirect effect: the backlog review report and its project-lead context, through the Skill bundles.
- Implementation work: CLI source for both scripts, the bundle build, the byte-match test, and the installed dogfood copy.
- Evidence source or testing type selected under current authority: the current collector and render tests with the generated files, and the byte-match test.
- Executor: the implementing agent.
- Accepted obligation or deferral route: none.

Authority: [Human Experience Contract](../../../.make-docs/system/contracts/human-experience-contract.md).
