# Package Copy and Validation Contract

## Purpose

Define how the generated package copy and release validation prove the shipped template path, not only the local development template path.

## Requirements

- `packages/cli/template/` is generated by the package preparation path, currently `node ../../scripts/copy-template-to-cli.mjs` through `packages/cli/package.json` `prepack`.
- Hand edits in `packages/cli/template/` are not source changes.
- Local development may resolve sibling `packages/docs/template/` first, but packed-package validation must exercise `packages/cli/template/` after copy/prepack.
- `npm run smoke:pack` and package dry-run checks are the primary package proof surfaces.
- Package README wording, tarball allowlist descriptions, maintainer docs, and smoke-pack expectations must agree with the accepted source-of-truth order.

## Acceptance Criteria

- The work backlog contains tasks for copy/prepack validation and packed-template parity.
- Package validation remains dry-run unless separately authorized.
- Any future helper script preserves the template-owned versus project-owned boundary.
