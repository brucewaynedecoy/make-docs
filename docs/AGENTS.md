# Documentation Router

Use `docs/` only as a router. Do not create generated files directly in this directory. Use a valid local resource body below `.make-docs/system/<type>/` first. When a required local body is absent, read its stable `make-docs://system/<type>/<posix-relative-path>` URI with `make-docs resource read`.
- For lifecycle order or skip/reorder/revisit decisions, read `.make-docs/system/references/lifecycle.md` or `make-docs://system/reference/lifecycle.md` and surface departures from the default arc.
- Source Markdown NEVER uses semantic line breaks; for path and link hygiene, use project-relative paths and relative Markdown links, and read `.make-docs/system/references/path-and-link-hygiene.md` or `make-docs://system/reference/path-and-link-hygiene.md`.
- For design docs, read `.make-docs/system/references/design-workflow.md` or `make-docs://system/reference/design-workflow.md`, `.make-docs/system/contracts/design-contract.md` or `make-docs://system/contract/design-contract.md`, and `.make-docs/system/templates/design.md` or `make-docs://system/template/design.md`, then continue in `docs/designs/`; for plans, read `.make-docs/system/references/planning-workflow.md` or `make-docs://system/reference/planning-workflow.md` and the selected local plan template below `.make-docs/system/templates/` or its `make-docs://system/template/<posix-relative-path>` URI, then continue in `docs/plans/`.
- For PRD or work generation, read `.make-docs/system/references/execution-workflow.md` or `make-docs://system/reference/execution-workflow.md`, `.make-docs/system/contracts/output-contract.md` or `make-docs://system/contract/output-contract.md`, and the selected local template below `.make-docs/system/templates/` or its `make-docs://system/template/<posix-relative-path>` URI, then continue in `docs/prd/` or `docs/work/`; work phase tasks use `- [ ] t1: ...` checkbox items and acceptance criteria use plain bullets.
- For requirement changes, read `.make-docs/system/references/prd-change-management.md` or `make-docs://system/reference/prd-change-management.md`; for gaps, drift, questions, risks, decisions, or closeout findings, first update `docs/prd/03-open-questions-and-risk-register.md` when it exists.
- Shared project material belongs in `docs/assets/project/`; audience assets belong in `docs/assets/<persona-slug>/`. Archives and history belong in `.make-docs/archive/`. Create asset directories only for needed content; keep routers at the assets root only.
- Built-in Personas have `slug`, `label`, `description`, and `primitive`: `user`, `User`, `People or agents that use the project.`, `user`; and `maintainer`, `Maintainer`, `People or agents that build, operate, maintain, or extend the project.`, `maintainer`. Either role can be human or agent. Merge `.make-docs/config.yaml` Personas by slug with both defaults; omitted built-in display fields inherit, and their primitives stay fixed. Custom entries need all four fields and a `user` or `maintainer` primitive. Missing/empty/comment-only config or an absent/empty list keeps defaults. Explicit null, malformed values, duplicates, unsafe slugs, or invalid primitives are errors. Reserve `project`, `archive`, `artifacts`, `library`, and `playbooks`; never silently remap a custom name. `make-docs project persona list` shows the effective set when the CLI is present.
- Asset router files: AGENTS.md, CLAUDE.md
- Without the CLI, use these defaults/config and create only the declared assets-root instruction files with the shared/audience paths, on-demand rule, and Store-only state rule. Do not infer filenames from your actor identity. If the declaration is absent or invalid, ask for an explicit project choice before router creation; content work can continue. Ordinary work may continue without optional CLI capture, with no local operational fallback or false capture claim.
- Before guide or system-resource coverage work, read `.make-docs/system/contracts/coverage-pass-contract.md` or `make-docs://system/contract/coverage-pass-contract.md`. Before guide writing, also read `.make-docs/system/contracts/guide-contract.md` or `make-docs://system/contract/guide-contract.md`, inspect existing guides for overlap, choose the verdict and target Persona, and use the matching local guide template below `.make-docs/system/templates/` or its `make-docs://system/template/<posix-relative-path>` URI.
- When work changes deferred obligations or Naive UAT, read `.make-docs/system/contracts/deferred-obligation-contract.md` or `make-docs://system/contract/deferred-obligation-contract.md`, `.make-docs/system/contracts/naive-uat-contract.md` or `make-docs://system/contract/naive-uat-contract.md`, and `.make-docs/system/references/naive-uat-workflow.md` or `make-docs://system/reference/naive-uat-workflow.md`. Each activated Naive-UAT run selects one eligible configured Persona and keeps tester qualification separate.
- Playbooks and Protocols are not current Make Docs product capabilities. Treat existing Playbook- or Protocol-shaped paths as legacy migration inputs.
- After guide work, reconcile overlapping guides when useful; use `## Future Coverage` inside guides for downstream-dependent guide updates instead of creating design docs, architecture decisions, or PRD risks only to remember future guide work.
- For closeout history records, read `.make-docs/system/contracts/history-record-contract.md` or `make-docs://system/contract/history-record-contract.md` and `.make-docs/system/templates/history-record.md` or `make-docs://system/template/history-record.md`, then use the current archive path owned by project authority.
- Prompts are first-class system resources. Read them by stable `make-docs://system/prompt/<posix-relative-path>` URI with `make-docs resource read` when a valid local body is absent. Their governing contracts own reusable rules.
- Do not infer optional Skills, plugins, Playbooks, Protocols, or unavailable policy from this router.
- **NEVER** add YAML front matter to `README.md` files.
