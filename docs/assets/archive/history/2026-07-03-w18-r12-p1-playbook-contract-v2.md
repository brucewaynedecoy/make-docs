# W18 R12 P1 Playbook Contract v2

## Changes

Implemented [Phase 1 of the W18 R12 backlog](../../../work/2026-07-03-w18-r12-playbook-authoring-ergonomics-and-cli-experience-remediation/01-playbook-contract-v2.md) per this historical record (retired action-PRD: `docs/prd/40-revise-playbook-authoring-contract-v2.md`) (R-DEP-1..3, R-FM-1, R-HEAD-1..2, R-MIG-1..4, R-RIPPLE-1..2, R-TEST-1), all thirteen phase tasks checked off, landing the clean-break v2 authoring contract that every later W18 R12 phase compiles against. The v1 dependency-table parser (`packages/cli/src/playbook/parser/dependency-table.ts`) is deleted and replaced by the dependencies-block parser at `packages/cli/src/playbook/parser/dependencies-block.ts`: the `## Dependencies` section carries one fenced `playbook` block with a top-level `dependencies:` list whose entries declare `id`, `kind`, `requirement`, an optional `probe` (the only field dependency-check generation may target, defaulting to `id`, resolved at parse time, and validated against the executable-token pattern), `source` as unparsed human provenance prose, `used_by` as a typed list, and `fallback`, under strict field discipline with exactly one authoritative `playbook` fence per governed section and fence/section top-level-key agreement. The frontmatter version keys shortened to `schema`/`workflowSchema`, the heading spine simplified to `## Inputs`/`## Workflow`/`## Gates`/`## Outputs` with the authority/precedence guidance folded into `## Inputs` prose, and the document schema identifier advanced to `make-docs.playbook.v2` (`PLAYBOOK_DOCUMENT_SCHEMA_ID` in `model.ts`; the workflow schema stays `make-docs.workflow.v1`). Two recorded implementer decisions keep the change additive downstream: the model retains the internal field names `schemaVersion`/`workflowSchemaVersion` fed by the v2 frontmatter keys, and `PlaybookDependency` gained `probe`/`probeDeclared` additively, so run-state, progression, and packaging consumers compile untouched. The clean break (nothing built on v1 was ever distributed — user decision) ships as six pointed error diagnostics naming the v2 replacement: PB-DEP-025 (v1 table), PB-FM-026 (old frontmatter keys), PB-DOC-027 (old heading spelling), PB-FM-028 (non-v2 schema identifier), PB-DOC-029 (fence/section key mismatch), and PB-DEP-030 (invalid probe token), with PB-DEP-009 repointed at a missing or malformed dependencies block; no warning path accepts an old form and the dropped deprecation diagnostics were confirmed absent. The dogfood order was honored per PRD 19: the playbook contract was fully rewritten to v2 and the default Playbook migrated upstream in `packages/docs/template/`, then both were re-seeded byte-identical into `.make-docs/contracts/system/playbook-contract.md` and `docs/assets/playbooks/agent/make-docs-lifecycle.playbook.md`, and both validate runnable with zero diagnostics. All forty test fixtures and the inline builders across fifteen test files migrated to v2 with a new shared `dependencyEntryLines` helper, eight new diagnostic fixtures landed, and new coverage includes probe defaulting and the F1 UAT repro shape (`git` with source `system install of git` resolving probe `git`) at the parser level. The suite closed at 879/879 across 54 files (+29) with the build green and smoke-pack exit 0. Honesty note: the packaging compiler's dependency materialization still scrapes `source` prose (`executableToken` in `materialization.ts`) — the model carries `probe` but nothing consumes it yet, so F1/[D-015](../../../prd/03-open-questions-and-risk-register.md) is NOT fixed end-to-end; that is [backlog Phase 2](../../../work/2026-07-03-w18-r12-playbook-authoring-ergonomics-and-cli-experience-remediation/02-compiler-probe-and-hint-retirement.md)'s scope. The [backlog index](../../../work/2026-07-03-w18-r12-playbook-authoring-ergonomics-and-cli-experience-remediation/00-index.md) stays `status: "active"` per the W18 R10/R11 convention.

Developer-guide coverage was `update-existing` on two owning guides; no new developer guide was warranted. The v1-spelling sweep across all fifteen developer guides found no other stale content: the `schemaVersion` occurrences in [Conformance Lab Scenario and Result Contracts](../../library/developer/conformance-lab-scenario-and-result-contracts.md) are the unrelated `conformance.scenario.v1`/`conformance.result.v1` schemas, the run-state record `schemaVersion` references in the runner and [store-boundaries](../../library/developer/maintainer-docs-assets-and-runtime-state-boundaries.md) guides are the record's own version field (deliberately kept, per the internal-naming decision), and the `PlaybookPackagePlan` `schemaVersion: 1` in the packaging guide is the plan schema — none is playbook frontmatter, so all were left unchanged.
