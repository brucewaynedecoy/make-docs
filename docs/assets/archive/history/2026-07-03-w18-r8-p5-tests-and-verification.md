### UAT Scenario: End-User Packaging Lifecycle From the Built CLI

Setup: `npm run build -w packages/cli`; `CLI="node <repo>/packages/cli/dist/index.js"`; a fresh temp project directory `$PROJ` outside the repo. Shorthand below: `PRECONDS` = `--precondition harness-supported=satisfied --precondition project-trusted=satisfied --precondition symlink-or-copy-mirror=satisfied`, and `EVIDENCE` = `--support-evidence-ref docs/prd/36-revise-playbook-packaging-compiler-and-harness-adapters.md`. All commands run from `$PROJ`.

1. `$CLI setup --yes` — expect a success summary and `.make-docs/manifest.json` with a minted project id (the writer requires an existing manifest for installed outputs); snapshot the file tree (`find . -type f | sort`).
2. Author `docs/assets/playbooks/user/uat-pack.playbook.md` by hand per the Playbook contract, with an authored summary (so the plan stays deterministic with no review gate), a `cli` dependency on `git`, a `reference` dependency on a repo-local doc, and no event-bound steps; also author `docs/assets/playbooks/user/uat-hooked.playbook.md` — the same shape plus one event-bound step — for the Pi leg. `$CLI run playbook validate user/uat-pack` and `$CLI run playbook validate user/uat-hooked` — expect zero errors and runnable. Authoring friction is itself a UAT observation.
3. `$CLI run package plan --source user/uat-pack --harness codex --output-kind plugin --surface native --scope project $EVIDENCE` — expect JSON with `status` plannable and no stops; the dry-run rendering includes `Planned payload files:` lines plus the distributable and degradation lines, so the whole generated tree is reviewable before any write; `support.status` is `provisional` and `support.tuple` carries `scenario`, `modelOrProvider`, and `runtime` as null. Save the returned `plan` object as `$PROJ/plan-codex.json`.
4. `$CLI run package write --plan-json plan-codex.json $PRECONDS` (no `--write`) — expect write diagnostics and generated-output records with the tree diff showing nothing new. Then re-run with `--write` — expect the canonical payload at `.make-docs/agentics/plugins/<id>/` exposed at `.codex/plugins/<id>`, containing `.codex-plugin/plugin.json`, `skills/<id>/SKILL.md` preserving the Playbook's intent, trigger, steps, references, and safety boundaries, `checks/git.sh`, `references/`, `registration/`, and the `.make-docs/{dependencies,registration,provenance,lifecycle,conformance}.json` records; the `.agents/plugins/marketplace.json` entry names the install path and package version (`.agents/plugins/` holds only that file); `grep -r '"kind": "make-docs' <payload>` finds nothing; and the write result carries the marketplace seam decision `generate-only` with its withhold reasons — nothing was registered anywhere.
5. Run a generated dependency check by hand: `sh .make-docs/agentics/plugins/<id>/checks/git.sh` — expect exit 0 with git installed, and expect the script text to be readable instructions rather than opaque tooling.
6. `$CLI run package plan --source user/uat-pack --harness codex --output-kind skills-bundle --surface agents-standard --scope project $EVIDENCE`, then write it — expect direct `.agents/skills/<id>/SKILL.md` discovery shape with no registration needed.
7. Pi leg: the same plan for `--harness pi --output-kind plugin --surface native` on `user/uat-pack` — expect the distributable lines to show the extension container (`extension.json` under `.pi/extensions/<id>`) and no hook files planned. Then plan `user/uat-hooked` against Pi — expect a fail-closed unsupported-surface stop for the event-bound step under the default `fail-closed` policy (the `degrade` choice has no CLI flag yet), with the stop message naming what is unsupported; nothing is written.
8. Stale-source stop: edit `uat-pack.playbook.md` (any content change), then `$CLI run package write --plan-json plan-codex.json $PRECONDS --write` — expect a digest-mismatch stop before any write naming the changed source, and a tree diff proving nothing changed; re-running the plan step recovers.
9. Local-modification guard: overwrite the generated `.make-docs/agentics/plugins/<id>/.codex-plugin/plugin.json` by hand, re-plan, and re-run the write — expect a modified-generated-output stop and the local edit preserved byte-for-byte.
10. `$CLI setup remove --backup` — expect backup copying exactly the Make Docs-owned outputs, removal of the canonical payloads and the `.codex`/`.agents` exposures with emptied harness directories pruned, and the user-authored Playbooks under `docs/assets/playbooks/user/` untouched; the final tree shows only user-authored files plus the backup.

Pass/fail reporting: every step names its observable expectation; the scenario fails if any expectation misses, if any stop writes files anyway, if any refusal message fails to name the actionable next step, or if any output claims more than provisional support. Record outcomes as a per-step checklist and file failures against the PRD 36 requirement the step exercises (R-COMP-1, R-TEST-2, R-DEPMAT-1, R-GEN-2, R-CAP-4/R-CAP-5, R-MKT-1/R-MKT-2, R-PROV-2, R-PROV-3). Every pass observation is a Make Docs file-shape and gating result only — harness recognition remains W18 R9's evidence bar.

Validation: full CLI suite 850/850 across 54 files this session with the build green, `npm run validate:defaults` exit 0, `python3 .make-docs/scripts/check_path_hygiene.py` clean, relative links in the touched docs verified to resolve, no guide promoted past `draft`, no unresolved placeholders, and `git diff --check` clean for every doc this session touched.
