# W18 R8 P4 Marketplace Seam, Provenance, and Lifecycle

## Changes

Implemented [Phase 4 of the W18 R8 backlog](../../../work/2026-07-01-w18-r8-playbook-packaging-compiler-and-harness-adapters/04-marketplace-registration-provenance-and-lifecycle.md) per [historical closeout](2026-07-03-w18-r8-p5-tests-and-verification.md) (retired action-PRD: `docs/prd/36-revise-playbook-packaging-compiler-and-harness-adapters.md`) R-MKT-1/R-MKT-2, R-PROV-1 through R-PROV-3, R-KEEP-1, and R-SCOPE-1, all eight phase tasks (t1 through t8) checked off. The marketplace and registration seam landed in the new `packages/cli/src/operations/playbook-packaging/registration-seam.ts` (R-MKT-1, R-MKT-2): the auto-registration opt-in reads the pre-existing `settings.marketplaceAutoRegistration` key of the global store's `~/.make-docs/config.json` through the store's own loader — the key was already in the W18 R10 `GlobalConfigSettings`, so zero store schema was defined here and an absent key means off (R-SCOPE-1) — and its shipped semantics are recognized-and-honored-by-refusing: every write result carries a `MarketplaceRegistrationSeamDecision` whose disposition is always `generate-only` with the withhold reasons declared (`auto-registration-opt-in-off`, `scope-not-global`, `global-approval-missing`, `auto-registration-unshipped-pending-conformance`), and even opt-in plus explicit global scope plus approval stays generate-only pending the W18 R9 evidence bar, so no auto-registration behavior ships enabled. The R-MKT-1 protection is a writer guard: `globalMarketplaceProtectionStops` fails closed if any planned write path — canonical payload, exposure root, or copy-mirror file — lands on a registration surface, with the user-home form requiring explicit global scope AND the named `global-marketplace-registration` approval; an audit found no shipped path writes to any marketplace surface (registration files land only at `registration/*` inside the distributable), so the guard is a tested invariant proven with a hostile fixture descriptor. Descriptor validation now enforces the registration-model/file pairing — a `marketplace-entry` model requires `registrationFiles` and `direct-discovery` forbids them, with `codex`, `claude-code`, and `pi` conforming — the generated Codex marketplace entry lowers `<user-home>/` to `~` and carries the package version so it is harness-usable as written, and `registration.json` names the seam key and its global-store home. The store README gained a line recording the packaging seam as the config key's consumer.

Provenance closed its query gap (R-PROV-1): the in-tree `provenance.json` already carried the full field list, so the new surface is `AgenticPackagingProvenance` on manifest ownership records — profile, adapter id, per-file source refs and digests, category, and tier — populated by the writer for payload and exposure entries and embedded in audit records, with per-file `files` traceability added to `provenance.json`. The classification fix (R-KEEP-1, t5): skills-bundle symlink exposures were mis-classified in `packages/cli/src/audit.ts` as `managed-file-modified`, which would have orphaned them on uninstall; the new `classifyPackagingSkillExposureRecord` classifies by the recorded symlink target, and tests prove all seven W18 R5 classifications distinct on the new multi-file trees with generated outputs never masquerading as Playbook source. Backup and uninstall (R-PROV-2) are proven end to end by the new `packages/cli/tests/playbook-packaging-lifecycle.test.ts`, which runs the real `runUninstallCommand` against written Codex plugin and Claude Code skills-bundle packages: backup copies exactly the audited owned outputs, and uninstall removes payload plus exposure, prunes emptied `.codex`/`.agents` directories without orphaning managed directories, and preserves user-authored files and locally modified generated files; `conformance.json` carries a `cleanlinessScenario` reference to the PRD 37-owned scenario (referenced, not implemented). Support-tuple binding (R-PROV-3) landed in the new `support-binding.ts`: `PackageSupportClaimTuple` carries all seven dimensions (scenario, harness, surface, scope, output kind, model or provider, runtime), with the evidence-owned dimensions `null` until W18 R9 and an `auto` surface counting as unbound, recorded on `PackagePlanSupport.tuple` and in `conformance.json` `tupleBinding.unboundDimensions`; `capSupportStatusForTupleBinding` plus a compiler fail-closed gate hold any `validated` claim provisional while unbound. One deliberate behavior change: the P3 planner had raised verified-Codex claims to `validated` on mere evidence refs — those are now capped to `provisional` per R-PROV-3, and a fully bound tuple is W18 R9's promotion path. The suite closed at 844/844 across 53 files (+16, in the new registration-seam and lifecycle test files) with the build green; no template-package resource was implied, so no upstream authoring was needed.

Developer-guide coverage was `update-existing` on [Playbook Packaging and Harness Adapters](../../library/developer/playbooks-development-packaging-and-harness-adapters.md), which owns the packaging topic: a new Marketplace Registration Seam section documents the config key, the recognized-and-honored-by-refusing semantics, the seam decision with its withhold reasons, the W18 R9 gating, and the `globalMarketplaceProtectionStops` guard; the operation-domain module list gained `registration-seam.ts` and `support-binding.ts`; the descriptor section gained the registration-model/file pairing validation and the harness-usable Codex marketplace entry; the provenance subsection documents the manifest/audit `AgenticPackagingProvenance` surfaces and per-file `files` traceability; Output Writers documents the classification fix; a new Support-Tuple Binding subsection documents the tuple, the dual gate, the deliberate P3 cap correction, and the W18 R9 promotion path; Fail Before Write gained the tuple gate and the marketplace-surface stop; Validation gained the registration-seam and lifecycle test coverage; and the Phase 4 Future Coverage bullet was resolved in favor of a Phase 5 D10-suite bullet plus the extended W18 R9 bullet. No new developer guide was warranted — the existing guide owns the topic exactly.

User-guide coverage was `update-existing` on [Packaging Shareable Playbook Workflows](../../library/user/playbooks-packaging-shareable-agent-workflows.md), because the seam and lifecycle behavior are user-visible facts: a new Registering a Package Is Manual section states that Make Docs never registers a package on the user's behalf, what to do by hand (the harness-usable Codex marketplace entry, the `registration/` folder, no registration needed for skills bundles), and that the `settings.marketplaceAutoRegistration` key exists but currently stays generate-only with every write reporting why installation was withheld; a new Uninstalling and Backing Up Installed Packages section states the owned-outputs-only backup, the payload-plus-exposure removal with safe directory pruning, and the preservation of user-authored and locally modified files, proven against real written packages while remaining honest that this is not harness-recognition evidence; and the support wording now explains the seven-dimension tuple, what provisional means under it, and that the earlier evidence-ref validated claim was overstated and is now capped. The W18 R9 Future Coverage bullet gained the auto-registration revisit. No new user guide was warranted.

PRD coverage was `risk-register-update` with no change doc, because the phase implemented existing PRD 36 requirements without changing the requirement surface. [R-017](../../../prd/03-open-questions-and-risk-register.md) advanced in place: the P4 registration and lifecycle pass was one of its two remaining close inputs, so its Decision now records the seam, the writer guard, the queryable provenance, the classification fix, the proven backup/uninstall, and the tuple binding, narrowing the remaining input to the W18 R9 conformance tuple evidence; it stays Open. [R-021](../../../prd/03-open-questions-and-risk-register.md) advanced in place with the tuple-binding note: the second, orthogonal support gate its evidence-outrunning half requires, including the deliberate correction of the P3 evidence-ref promotion; it stays Open pending the W18 R9 recorded scenarios. No other register item needed movement — R-022 concerns real-harness conformance availability, which this phase references through the `cleanlinessScenario` pointer but does not advance, and R-016 is runner-side — the PRD 36 baseline text needed no change note (implementation, not requirement change), and `docs/prd/00-index.md` needed no maintenance.

Testing and UAT coverage beyond the suite was `none`: the phase's observable surface is the seam decision JSON, the guard stops, the manifest/audit provenance records, and the lifecycle behavior, all asserted by the 844-test suite including the real-uninstall runs against written packages in temp repos, and the meaningful manual moment — a harness actually consuming a registration file or recognizing an installed package — is exactly the recognition evidence reserved for the W18 R9 conformance lineage, so a manual pass now would re-drive covered assertions without adding signal.

Validation: full CLI suite 844/844 across 53 files this session, `npm run validate:defaults` exit 0, `python3 .make-docs/scripts/check_path_hygiene.py` clean, relative links in the touched docs verified to resolve, no guide promoted past `draft`, no unresolved placeholders, and `git diff --check` clean for every doc this session touched.
