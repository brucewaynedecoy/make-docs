# W18 R8 P3 Verified Adapter Contracts

## Changes

Implemented [Phase 3 of the W18 R8 backlog](../../../work/2026-07-01-w18-r8-playbook-packaging-compiler-and-harness-adapters/03-verified-adapter-contracts.md) per [historical closeout](2026-07-03-w18-r8-p5-tests-and-verification.md) (retired action-PRD: `docs/prd/36-revise-playbook-packaging-compiler-and-harness-adapters.md`) R-ADAPT-1 through R-ADAPT-5 with R-PROV-3, R-CAP-4/R-CAP-5, R-KEEP-1, and R-TEST-2/R-TEST-3/R-TEST-5 honored, all twelve phase tasks (t1 through t12) checked off. Verification now rides every adapter declaration (R-ADAPT-1): `deriveAdapterDeclarationCore` copies the descriptor's verification block — `status`, `reference`, `provisionalNotes`, and `contractDigest` — onto `HarnessPackageAdapterDeclaration.verification`, and `validateHarnessAdapterDeclaration` rejects any declaration without it, so no adapter can ship unverifiable. Status gating is dual-enforced (R-ADAPT-1, R-PROV-3): the new `capSupportStatusForVerification` caps a planner support status of `validated` to `provisional` unless the harness contract is `verified`, recording the gate input in `deterministicDerivations.adapterVerification`, while the compiler independently fails closed before any write with a `missing-support-evidence` stop when a plan claims validated support against an unverified adapter; unverified adapters produce only provisional or export-only output with no support claim, and the compiled `.make-docs/conformance.json` embeds the applied `adapterVerification` gate (status, reference, contract digest). Re-verification is structural (an implementer decision): `computeHarnessContractDigest` fingerprints the declared contract surface — placements, manifest filenames, skill templates, registration files and model, hosted primitives, hook points, exposure modes — a `verified` descriptor records the digest as a source literal, and descriptor validation recomputes it on every load so declaration drift fails closed demanding re-verification, while provisional contracts carry a `null` digest but must state what remains unverified.

The Codex contract is corrected (R-ADAPT-2): the assumed `.agents/plugins/{packageId}` placement root is gone — plugin folders install at the Make Docs-chosen D9 roots `.codex/plugins/{packageId}` (project), `~/.codex/plugins/{packageId}` (global), and `.make-docs/exports/playbook-packages/{packageId}` (export-only) that the generated `.agents/plugins/marketplace.json` entry references, with `.agents/plugins/` holding only the marketplace file — the plugin payload is the Phase 2 compiled tree (the `.codex-plugin/plugin.json` folder), and the skills bundle is direct `.agents/skills/{id}/SKILL.md` with symlink or copy-mirror exposure. Codex is the one `verified` descriptor, citing the design's D6/R-ADAPT-2 statement and [the playbook architecture artifact](../../artifacts/playbook-architecture.md) Section 8 at digest `sha256:2033146ce7fa5b71`, with MCP-server hosting inside the plugin container flagged as residual inference. Claude Code landed with its lowering pinned per R-ADAPT-3 — plugin `.claude/plugins/{id}/plugin.json`, skill `.claude/skills/{id}/SKILL.md`, portable `.agents/skills/{id}/SKILL.md`, session events mapped to Claude Code hook points — and stays `provisional` until reviewed against the real contract. The new Pi adapter landed per R-ADAPT-4 with zero planner or resolver changes, proving the R-KEEP-1 additive recipe: a descriptor-derived declaration only, whose native profile lowers to the pi-extension container (`extension.json` at `.pi/extensions/{id}`), whose event-bound steps degrade to documented skill instructions under the `degrade` policy or fail closed by default with no hook artifact ever, and whose portable profile lowers to agents-standard skills; its paths are fully inferred and `provisional`. The R-ADAPT-5 fail-closed audit confirmed all four paths — unknown harness, unsupported output kind, unsupported surface, un-honorable scope — stop before any write, and fixed a real writer gap: the writer crashed building an exposure record from an unsupported resolution with an empty package path and now skips it and fails closed. A new fixture-limited adapter (native-plugin-only, no hooks) exercises the unsupported stops, with writer tests proving nothing is written. All support statuses remain tuple-bound and provisional pending W18 R9 (R-TEST-5). The suite closed at 828/828 across 51 files (+22 in the new `packages/cli/tests/playbook-packaging-adapters.test.ts`, shape and gating assertions only) with the build green; no template-package resource was implied, so no upstream authoring was needed.

Developer-guide coverage was `update-existing` on [Playbook Packaging and Harness Adapters](../../library/developer/playbooks-development-packaging-and-harness-adapters.md), which owns the packaging topic: the descriptor section now documents the verification block with `contractDigest`, the verification copy onto adapter declarations with declaration validation rejecting its absence, the corrected per-harness descriptor bullets (explicitly noting the `.agents/plugins/{packageId}` root is gone), a new Verification Status and Support Gating subsection with the per-adapter status table, citations, the two enforcement points, and the `conformance.json` embed, and a new Contract-Digest Re-Verification subsection; the Harness Adapters section now lists `pi` alongside `codex` and `claude-code` with the Pi degradation behavior and both fixture adapters; the add-a-harness recipe is marked proven by Pi's zero-planner-change landing; Fail Before Write gains the `missing-support-evidence` stop, the four-path audit, and the fixed writer gap; Validation gains the new adapter test coverage; and the Phase 3 Future Coverage bullet was resolved in favor of the remaining Phase 4 registration-seam bullet plus a W18 R9 conformance-and-review bullet. No new developer guide was warranted — the existing guide owns the topic exactly.

User-guide coverage was `update-existing` on [Packaging Shareable Playbook Workflows](../../library/user/playbooks-packaging-shareable-agent-workflows.md), because the harness landing spots are now user-visible facts: a new Where Generated Packages Land section states where Codex packages land (`.codex/plugins/<package-id>` plus the `.agents/plugins/marketplace.json` entry, `.agents/skills/<id>/SKILL.md` for bundles), the Claude Code and Pi locations, and the export-only path; the harness list now names Pi with its no-hooks extension behavior; the per-harness verification honesty replaces the blanket provisional caveat (Codex verified against the documented contract, Claude Code and Pi still provisional with what provisional means for a user); the support wording states that validated claims require verified contracts and that Make Docs caps and stops otherwise; and the no-recognition-claims caveat is kept until W18 R9.
