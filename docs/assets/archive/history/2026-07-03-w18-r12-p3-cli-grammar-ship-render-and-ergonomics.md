# W18 R12 P3 CLI Grammar, Ship, Render, and Ergonomics

## Changes

Implemented [Phase 3 of the W18 R12 backlog](../../../work/2026-07-03-w18-r12-playbook-authoring-ergonomics-and-cli-experience-remediation/03-cli-grammar-ship-render-and-ergonomics.md) per [historical closeout](2026-07-03-w18-r12-p4-verification-and-conformance-reconciliation.md) (retired action-PRD: `docs/prd/41-revise-cli-human-experience-and-package-grammar.md`) (R-INV-1, R-RENDER-1..3, R-GRAM-1..3, R-RUNID-1, R-FLAG-1..2, R-NOISE-1, R-TEST-4..6), all fourteen phase tasks checked off, layering the human experience over the remediated operations without moving a byte agents depend on. Grammar (R-GRAM-1..2): the packaging surface is intent-named — `run package preview` is a CLI SPELLING over the unchanged `package.write` operation with a dry-run context overlay, declared once in `RUN_CLI_SPELLINGS` in `packages/cli/src/run/cli.ts` with `listRunCliSpellings` as the conformance seam, so no new registry identifier exists and the MCP surface never sees it; `run package write` writes with every precondition, digest-mismatch, ownership-conflict, and fail-before-write stop enforced; the retired `--write` flag fails with guidance naming `preview`/`write`/`plan --output`/`ship`; and `plan --output <path>` writes the reviewable plan object (exactly what `--plan-json` consumes) at the CLI surface, with `package.plan` deliberately staying read-classified because reclassification would change agent-facing gating (R-INV-1). Ship (R-GRAM-3): `package.ship` is a new registered write operation at `packages/cli/src/operations/package/ops/ship.ts` running plan → preview → write as nested `invokeOperation` calls so the operation core gates every leg uniformly; it aborts at the first stop, unresolved proposal, or unreviewed decision with `{status: "aborted", stage, guidance}` naming the granular command, ships zero-unresolved plans end-to-end with the classification write recorded, returns `"planned"` under a dry-run context, and surfaces as `run package ship` plus the derived `make_docs_package_ship` — the phase's only, additive, MCP surface diff, with the derivation/consistency pins extended accordingly. Render (R-RENDER-1..3): the new `packages/cli/src/run/render.ts` sits at the seam where `printJson(invocation.value)` sat, keyed by the previously unused `OperationRenderMode` — `--json` always emits the full result, non-TTY defaults to the same full JSON proven byte-identical with `toBe` string assertions (the R-INV-1 proof, with an injectable `isTty` seam on `runRunCommand` because vitest stdout is never a TTY), and a TTY renders per-family human text: run-state transitions print the execution report, a compact run line, the current hints, a full-record reference, and the exact next command (registry-derived, never hand-maintained) as the last line, with bespoke renderers for `playbook.next`, `playbook.catalog`, and the package pipeline plus a defensive generic fallback that dumps JSON on any shape surprise so a renderer can never fail an operation; the capability snapshot renders once at `start` and later renderings reference `--json` instead of restating it (X7), and the evidence log is never echoed in text mode. Ergonomics: `resolvePlaybookRunIdSelector` in `run-state.ts` resolves every existing-run `--run-id` acceptor (`status`, `next`, `advance`, `gate`, `resume`, `close`, `run.export`) — exact wins, an unambiguous prefix resolves, ambiguity fails listing candidates, and two recorded implementer decisions preserve invariance: a no-match value and any store failure during listing pass the raw value through so pre-existing error text stays byte-identical, while `--last` (latest `createdAt`, run-id tie-break) has no pass-through; `--repo-root` defaults to the nearest ancestor carrying `.make-docs/manifest.json` (R-FLAG-1); the new `packaging.preconditions` block in `.make-docs/config.yaml` (`MakeDocsPackagingConfig` in `config.ts`) is absorbed as defaults by the `write`/`preview`/`ship` adapters with explicit `--precondition` flags always overriding per key and a missing block changing nothing (R-FLAG-2); and `packages/cli/src/run/warnings.ts` wraps `process.emitWarning` at the bin entry filtering only the `ExperimentalWarning` type with the SQLite message — every other warning passes through, tested (R-NOISE-1). The R-TEST-4..6 suites landed in the new `packages/cli/tests/run-cli-experience.test.ts`, and the full suite closed at 907/907 across 55 files (+22) with the build green.
