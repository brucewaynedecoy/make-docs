# W18 R8 P2 Compiler Output Writer and Dependency Materialization

## Changes

Implemented [Phase 2 of the W18 R8 backlog](../../../work/2026-07-01-w18-r8-playbook-packaging-compiler-and-harness-adapters/02-compiler-output-writer-and-dependency-materialization.md) per [PRD 36](../../../prd/36-revise-playbook-packaging-compiler-and-harness-adapters.md) R-COMP-1 through R-COMP-3, R-GEN-1/R-GEN-2, and R-DEPMAT-1 with R-KEEP-1, R-SCOPE-1, and R-MKT-1 preserved, all fourteen phase tasks (t1 through t14) checked off. The new `packages/cli/src/operations/playbook-packaging/compiler.ts` fixes the triggering defect: `compilePackageInventory` produces the distributable inventory as a pure function of the parsed W18 R6 Playbook models plus the target's capability descriptor — a `SKILL.md` per source Playbook preserving workflow intent, triggers, step instructions, references, and safety boundaries; copied-or-linked references; dependency-check and helper scripts; the harness-native manifest from the descriptor's `manifestFilename` and `skillFileTemplate`; `hooks/hooks.json` from native lifecycle-event lowerings; `registration/*` files from the descriptor's `registrationFiles`, generated but never registered (R-MKT-1); and `.make-docs/{dependencies,registration,provenance,lifecycle,conformance}.json` records inside the container — while `writers.ts` was rebuilt to stage that compiled tree and the `renderPackageContent` path whose plugin output carried `kind: make-docs.playbook-package.plugin` is deleted, so no packaging path emits a Make Docs descriptor as an installable artifact (R-COMP-1). `loadCompiledSource` is shared with the planner so models are parsed once (R-SCOPE-1), and `loadPackageSourcesForWrite` digest-verifies plan sources at write time. The D9 file-organization decisions ride the `compiler.ts` doc comment: manifest containers use `skills/{skillId}/SKILL.md`, a single-skill `skills-directory` puts `SKILL.md` at the container root so `.agents/skills/{id}/SKILL.md` discovery holds, multi-skill portable bundles emit a root index plus per-skill directories, shared `references/`, `checks/`, `scripts/`, `hooks/`, and `registration/` sit at the container root, and the manifest `version` is a constant `0.1.0` pending lifecycle lineage.

The new `materialization.ts` implements R-DEPMAT-1 per kind: `cli`/`package-manager` emit executable `checks/{id}.sh` scripts plus human instructions, with Make Docs `cli` dependencies carrying `# stable-reference: operation:{id}` and the human command form derived via `operationCliPath` at compile time, never hardcoded; `skill`/`plugin` become manifest references where the container hosts the primitive and explicit declared degradation in the skill text otherwise; `mcp`/`external-service` emit `runtimeCheck` metadata plus an availability check script; `reference` is copied into `references/{id}/` when repo-local (the redistribution-allowed heuristic) and linked otherwise, with unresolved required references failing closed; `playbook` becomes a bundled-skill pointer when in the bundle and a referenced-playbook entry when not; and `script`/`asset`, which R-DEPMAT-1 assigns no artifact, materialize documented-only (D9). Generation stays two-tier (R-GEN-1): the deterministic tier owns inventory, manifest structure, dependency checks, and digests, skill descriptions are deterministic from an authored source summary or review-gated agent proposals gaining authority only on plan acceptance, and `provenance.json` carries `generationTiers` grouping every field by tier alongside source refs and digests, profile, adapter id, generated files, ownership, and support status. Fail-before-write (R-GEN-2) is enforced in both planner and writer: unresolved proposals or review, ownership conflicts, missing dependencies, unsupported surfaces, stale or missing sources, a missing manifest, and unreviewed stale-output removal all stop non-interactive runs before writing. The PRD 28 exposure plumbing is preserved byte-for-byte (R-COMP-2) — canonical payload under `.make-docs/agentics/{plugins|skills}/{id}`, symlink or copy-mirror exposure, per-file manifest ownership, backup-reviewed stale removal, owned-output-only cleanup — with a new test asserting per-file ownership for both exposure modes. The suite closed at 806/806 across 50 files (+11 in the new `packages/cli/tests/playbook-packaging-compiler.test.ts`, including the R-TEST-2 Codex shape assertions and the R-MKT-1 generate-but-do-not-register test, all noted as shape-only per R-TEST-5) with the build green; no template-package resource was implied, so no upstream authoring was needed.

Developer-guide coverage was `update-existing` on [Playbook Packaging and Harness Adapters](../../library/developer/playbooks-development-packaging-and-harness-adapters.md), which owns the packaging topic: it gained a Packaging Compiler section (inventory as a pure function of model plus descriptor, the emitted inventory categories, shared source loading with write-time digest verification, the D9 file-organization decisions, the per-kind dependency materialization table with the stable-operation-reference mechanism, the two-tier provenance record, and the consolidated fail-before-write condition set), a rewritten Output Writers section that retires the descriptor-payload wording, names the deleted `renderPackageContent` defect, and states the byte-for-byte R-COMP-2 plumbing preservation, module-list entries for `compiler.ts` and `materialization.ts`, plan-time inventory and proposal behavior in Package Plans, the honest `unsupportedPrimitivePolicy` surface state (registry input and MCP exposed, no CLI flag yet), and the new compiler test coverage. The Phase 2 Future Coverage bullet was resolved and replaced with a Phase 4 registration-seam bullet alongside the remaining Phase 3 verification bullet. No new developer guide was warranted — the existing guide owns the topic exactly.

User-guide coverage was `update-existing` on [Packaging Shareable Playbook Workflows](../../library/user/playbooks-packaging-shareable-agent-workflows.md), because packaging now has a real user-visible surface: a new What a Generated Package Contains section describes the harness-native tree a user will find — per-Playbook `SKILL.md` files preserving the workflow, the harness manifest, copied references, runnable `checks/` dependency scripts, hooks, never-auto-registered registration files, and the `.make-docs/` bookkeeping records — with two honest caveats that layouts stay provisional until Phase 3 verification and no recognition claim exists until W18 R9 evidence. The review-flow text now explains that plans list the exact planned payload files, that missing summaries become reviewable description proposals, and that writes stop on changed sources with a re-plan instruction. Future Coverage was resolved for what landed and re-anchored: the friendlier-surface bullet now records that the compiler is real but no first-class command or `unsupportedPrimitivePolicy` CLI flag shipped, a Phase 3 verification bullet was added, and the W18 R9 bullet remains. No new user guide was warranted.

PRD coverage was `risk-register-update` with no change doc, because the phase implemented existing PRD 36 requirements without changing the requirement surface. [R-017](../../../prd/03-open-questions-and-risk-register.md) advanced materially in place: its Decision now records that the triggering writer defect is fixed — the descriptor-payload path deleted, the pure-function inventory, per-kind materialization with stable operation references, two-tier `generationTiers` provenance, dual-enforced fail-before-write with digest-verified sources, and byte-for-byte plumbing preservation at 806/806 — and states that the compiler tests are shape-only per R-TEST-5, so the item stays Open pending the P3 verified adapters, the P4 registration and lifecycle pass, and the W18 R9 conformance tuple evidence its close bar requires. [R-021](../../../prd/03-open-questions-and-risk-register.md) advanced in place: the compiler now emits the declared Codex shapes for real (`.codex-plugin/plugin.json` plus marketplace registration, `.agents/skills/{id}/SKILL.md`), shape-asserted by R-TEST-1/R-TEST-2 with recognition evidence explicitly withheld, registration never auto-mutated, and all support statuses still provisional; it stays Open pending Phase 3 verification and W18 R9 evidence. No other register item needed movement (R-016 is runner-side and untouched; R-022 concerns real-harness conformance availability, which this phase does not advance), the PRD 36 baseline text needed no change note (implementation, not requirement change), and `docs/prd/00-index.md` needed no maintenance.

Testing and UAT coverage beyond the suite was `none`: the phase's observable surface is the plan/write JSON and the generated tree, both asserted end to end by the 806-test suite including real writes through the exposure plumbing in temp repos, and the meaningful manual moment for packaging — installing a generated package in a real harness — is exactly the recognition evidence R-TEST-5 reserves for the W18 R8 P3 verification pass and the W18 R9 conformance lineage, so a manual pass now would re-drive covered shape assertions without adding signal.

Validation: full CLI suite 806/806 across 50 files re-run this session, `npm run validate:defaults` exit 0, `python3 .make-docs/scripts/check_path_hygiene.py` clean, relative links in the touched docs verified to resolve, no guide promoted past `draft`, no unresolved placeholders, and `git diff --check` clean for every doc this session touched.
