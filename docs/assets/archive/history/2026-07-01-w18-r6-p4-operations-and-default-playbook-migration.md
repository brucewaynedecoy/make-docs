# W18 R6 P4 Operations Wiring and Default Playbook Migration

## Changes

Implemented W18 R6 Phase 4 by wiring the Phase 2/3 library into the operation surface and migrating the shipped default Playbook, per R-MODEL-6, R-DOC-2, and R-AUTH-5 of [PRD 34](../../../prd/34-revise-playbook-contract-and-model.md). The new module at `packages/cli/src/operations/playbook/contract.ts` implements `playbook.validate` and `playbook.catalog` as thin wrappers over `parseAndValidatePlaybook`: every parsed fact and every diagnostic comes solely from the library, nothing diagnostic-shaped lives only in the operation layer (R-MODEL-2, R-MODEL-6), and the stable `playbook.validate`/`playbook.catalog` identifiers are consumed as an external contract minted by the W18 R11 operation-registry lineage (R-SCOPE-2). Both operations are surfaced on the CLI (`make-docs operations playbook-validate [refs...]` accepting explicit `.md` paths or canonical `persona/slug` references and defaulting to every detected Playbook, plus `playbook-catalog`) and on MCP (`make_docs_playbook_validate` new; `make_docs_playbook_catalog` repointed onto the library-backed operation) inside the modular operation-domain boundary per the PRD 25 pattern. The catalog enumerates Playbooks by canonical reference — frontmatter `id` when present, otherwise `persona/slug` (R-DOC-4) — with frontmatter identity, file form (`playbook-suffix` versus `deprecated-plain`), runnable flag, and error/warning counts, and PB-FILE-007 rename warnings surface in the catalog diagnostics (R-DOC-2). The legacy internal `buildPlaybookCatalog` was retained behind the runner lineage — resolver, run-state, invoke, and packaging, untouched per R-SCOPE-1 — with minimal suffix-form support so `playbook-resolve agent/make-docs-lifecycle` keeps working. The default Playbook was migrated upstream-first to `packages/docs/template/docs/assets/playbooks/agent/make-docs-lifecycle.playbook.md` with a byte-identical dogfood copy at [docs/assets/playbooks/agent/make-docs-lifecycle.playbook.md](../../playbooks/agent/make-docs-lifecycle.playbook.md) and the old plain files deleted in both locations (R-AUTH-1, R-AUTH-5): eleven-heading spine, original lifecycle content preserved under `## Step Guidance`, a seven-row dependency registry with zero warnings, and an eight-step workflow contract including a deterministic `operation: playbook.validate` step, a human gate with gate semantics, and an event-bound `on-pre-commit` step. It validates with zero errors and zero warnings in both locations, and new consistency tests assert this plus that all shipped default Playbooks validate clean (R-TEST-3). The t7 filename audit updated the rules catalog path, `scripts/smoke-pack.mjs`, the README link, two library guides, one active design-doc link, and install/consistency test paths, leaving historical PRD, plan, artifact, and archive references as history; t8 confirmed `packages/cli/template/` is gitignored and build-generated with no hand edits. All eight tasks in [the Phase 4 backlog file](../../../work/2026-07-01-w18-r6-playbook-contract-and-model/04-operations-and-default-playbook-migration.md) are checked off.

PRD coverage was `risk-register-update` plus a drift check that returned `none`. The R-018 Decision cell in [the open questions and risk register](../../../prd/03-open-questions-and-risk-register.md) now records the Phase 4 landing — the library-backed operations on both surfaces with registry-consumed identifiers, the upstream-first default-Playbook migration with zero-diagnostic validation in both locations, and the shipped-defaults consistency test — while keeping the item Open with per-code failing fixtures and upstream-contract-copy parity checks remaining through Phase 5; the item number, heading, Open status, and Follow-Up were preserved with a Decision-cell-only edit. The requirement-surface check found no drift: the implementation's PB-FILE-007 deprecation path matches PRD 34 R-DOC-2 and R-MODEL-5 verbatim (suffix form required, plain `kind: playbook` detected as deprecated with the rename warning), the operation surfacing matches R-MODEL-6 (operations wrap the library so a language server would produce identical diagnostics), the migration satisfies R-AUTH-1/R-AUTH-5/R-TEST-3 as written, and PRD 29 already carries the Phase 1 supersession notes pointing its filename, frontmatter, body-contract, and orchestration-hint sections at PRD 34, so nothing in PRD 29 describes the old form as active. No new change doc was warranted because the phase implemented existing requirements.

Guide coverage was `update-existing` for both personas, executing the Future Coverage bullets that were gated on exactly this phase. The developer [runner architecture guide](../../library/developer/playbooks-development-runner-architecture.md) had its Catalog Contract Validation section swapped from the W18 R4 catalog-validation description to the landed operation behavior: the library-backed `playbook.validate` and `playbook.catalog` semantics on CLI and MCP, the diagnostic record shape, both file forms with the PB-FILE-007 deprecation path, the registry-consumed identifiers, the note that the twenty-four-code catalog is now runtime surface pinned by the contract/catalog machine-check, and the note that the pre-contract catalog implementation survives only behind the runner lineage until W18 R7; the resolver-semantics filename form, the operations list, and the shipped-defaults section (zero-diagnostic validation plus consistency test) were refreshed, the fired Future Coverage bullet was removed, and the run-state/invoke sections stay owned by the remaining W18 R7 bullet. The user [running-playbooks guide](../../library/user/playbooks-running-make-docs-workflows.md) gained the `<slug>.playbook.md` filename form with the deprecated-form rename warning, a link to the Playbook contract as the schema authority, `playbook-validate`/`playbook-catalog` CLI usage with the migrated default's canonical `agent/make-docs-lifecycle` reference, a description of validate output (stable codes, severities, locations, messages, fix hints, runnable at zero errors), and the MCP tool names. The deferred reader-facing contract-projection guide was explicitly deferred again (`link-only`): the contract remains normative and linkable on its own, the user guide now covers the user-visible validate/catalog surface directly, and a projection written before Phase 5's fixture/parity hardening and the W18 R7 runner consumption could describe still-shifting behavior; the decision and its post-Phase-5 revisit trigger are recorded in the guide's Future Coverage bullet. Manual-test/UAT coverage remains `none` (deferred) until W18 R6 wave completion per user instruction; the natural UAT — a `playbook-validate` run over the installed default — is now available for that pass.

Validation: the full CLI suite passed 537/537 tests across 32 files at the implementation checkpoint with build and `smoke:pack` green (the tree also carrying concurrent W18 R10 work), `diff -q` confirms the upstream and dogfood copies of the migrated Playbook are byte-identical, `check_path_hygiene.py` reports zero errors, `git diff --check` is clean, the jdocmunch index was refreshed and reports zero broken links in the docs touched by this closeout, and a repo-wide search for live `make-docs-lifecycle.md` references outside archives, work, plans, and PRDs found only historical prose in migration-lineage designs and one artifact describing the pre-migration path as the thing being migrated, with no live links stranded.
