# W18 R12 P2 Compiler Probe and Hint Retirement

## Changes

Implemented [Phase 2 of the W18 R12 backlog](../../../work/2026-07-03-w18-r12-playbook-authoring-ergonomics-and-cli-experience-remediation/02-compiler-probe-and-hint-retirement.md) per [historical closeout](2026-07-03-w18-r12-p1-playbook-contract-v2.md) (retired action-PRD: `docs/prd/40-revise-playbook-authoring-contract-v2.md`) (R-DEP-3, R-FIX-1, R-TEST-2) and [historical closeout](2026-07-03-w18-r12-p4-verification-and-conformance-reconciliation.md) (retired action-PRD: `docs/prd/41-revise-cli-human-experience-and-package-grammar.md`) (R-FIX-2, R-TEST-3), all eight phase tasks checked off, fixing both confirmed UAT defects on top of the Phase 1 model. F1/[D-015](../../../prd/03-open-questions-and-risk-register.md): `executableToken` is deleted from `packages/cli/src/operations/playbook-packaging/materialization.ts` and materialization is probe-only — generated `cli` and `package-manager` checks probe the model's resolved `probe` (declared value or the `id` default) via `command -v`; the `skill`/`plugin` manifest reference identifier, the `mcp`/`external-service` `runtimeCheck` target and check script target, and the `playbook` reference identifier are all the resolved probe, with provenance prose riding human instruction text verbatim; `package-manager` `source` survives only in the human "install per:" text; and `script`/`asset` `source` is display-only. Two recorded W18 R12 P2 implementer decisions ride the module doc: a `cli` dependency on Make Docs declares the stable operation identifier ON `probe`, gated by `hasOperation(probe)` (PRD 40 and the design are silent on where the identifier moves after the `source`-prose break; the contract's worked example supports the shape), and `reference` locators are the probe-rule exception — references generate no checks and the executable-token pattern cannot express dot-led paths or URLs, so the locator stays the whole declared `source` value consumed verbatim, never parsed. `MaterializedDependency` additively gained `probe`, emitted into the distributable's `.make-docs/dependencies.json`, and a search-verified invariant confirms no code path under `packages/cli/` parses dependency `source` for machine meaning. F2/[D-016](../../../prd/03-open-questions-and-risk-register.md): hints are subject-scoped through the additive `hintSubjects` map on `PlaybookRunState` (the record stays `schemaVersion` 2 — readers default an absent map to `{}`, so pre-change records and previously exported run artifacts load unchanged with legacy hints reading as run-scoped, and no store migration pass is required, per the PRD 38 schema-versioning rules), and the new `settleGuidanceHints` seam in `packages/cli/src/operations/playbook/progression.ts` retires every hint whose subject reached a resolved status (`completed`, `failed`, `skipped`, `cancelled`, or dropped from the workflow) before appending the transition's own subject-scoped hints, applied on `advance` (both the outcome and hold paths), `gate`, and all three `resume` paths; `playbook.close` clears all guidance hints so a closed run carries none; caller-supplied and capability-fallback hints are run-scoped and retire only at close; and the `evidenceLog` is untouched by every hint operation. Proof tests pin both fixes: the D-015 UAT repro end-to-end (`git` with source `system install of git` generating a check probing `git`; a declared `gh` probe winning over the `github-cli` id; adversarial prose across kinds so any future prose-derived token fails the suite) and the hint retirement matrix including the failed-step swap, the rejected gate, the pre-change-record migration, and the legacy-artifact import. The suite closed at 885/885 across 54 files (+6) with the build green.

Developer-guide coverage was `update-existing` on the same two owning guides as Phase 1; no new developer guide was warranted. [Playbook Packaging and Harness Adapters](../../library/developer/playbooks-development-packaging-and-harness-adapters.md) owns dependency materialization: its Dependency Materialization section was rewritten to the probe-only rule — the deleted `executableToken`, the per-kind probe consumption in the materialization table (including the `command -v` check shape and the `package-manager` install-per text), the operation-identifier-on-probe and reference-locator-exception implementer decisions, and the `.make-docs/dependencies.json` probe emission — the compiler-coverage paragraph gained the F1 regression-fixture description, and both the honest Phase-2-pending D-015 note and the Phase 2 Future Coverage bullet are resolved with an explicit resolution line. [Run Playbook Runner Architecture](../../library/developer/playbooks-development-runner-architecture.md) owns hints/evidence semantics: its Progression Engine section gained the hint-retirement paragraph — the subject-scoped `hintSubjects` map, the single `settleGuidanceHints` seam and its retirement points, close-clears-all, run-scoped versus subject-scoped retirement, the additive schema-compat path, the untouched evidence log, and the extender rule to route every hint through the seam — the Run State record enumeration now points at it, and PRD 41 was added to `related` and Related Resources.

User-guide coverage was `update-existing` on both playbook user guides; no new user guide was warranted. [Packaging Shareable Playbook Workflows](../../library/user/playbooks-packaging-shareable-agent-workflows.md) had its `checks/` D-015 caveat resolved: the bullet now states that a check verifies the dependency's declared probe and shows how a user controls it from the fenced `dependencies` block (`probe:` naming the exact binary, defaulting to the `id`, with `source` notes like `system install of git` never influencing the check), and the matching Future Coverage bullet is resolved with an explicit resolution line. [Running Make Docs Playbooks](../../library/user/playbooks-running-make-docs-workflows.md) gained a short guidance-hints paragraph in Driving a Run from Start to Close: hints reflect only unresolved work, resolved-subject advice is retired automatically, a closed run carries no guidance hints, and the evidence log keeps the full history. Deliberately not claimed anywhere: the `plan`/`preview`/`write` CLI grammar and the render layer, which are Phase 3's scope.

PRD coverage was `risk-register-update` with no change doc, because the phase implemented existing PRD 40 and PRD 41 requirements without changing the requirement surface. [D-015](../../../prd/03-open-questions-and-risk-register.md) is CLOSED: its literal close bar — checks probe the declared `probe` or `id`, nothing parses `source` for machine meaning anywhere, and the UAT repro passes — is met end-to-end, recorded in a Resolution block per the register's closure pattern (R-019 precedent) with the Follow-Up narrowed to the standing regression guard. [D-016](../../../prd/03-open-questions-and-risk-register.md) is CLOSED the same way: resolved-subject hints retire on each transition, a closed run carries no guidance hints, and the evidence log is unchanged, with the additive schema-compat decision recorded in the Resolution. [R-026](../../../prd/03-open-questions-and-risk-register.md) advanced in place: its Decision records Phase 2 complete (all eight tasks, both defects closed, 885/885) and its stays-Open scope narrowed to Phases 3–4 — the CLI grammar/render layer and the PRD 37/W18 R9 reconciliation — before W18 R9 may execute. No renumbering, no new PRD docs, and no index movement was needed: per the Phase 1 precedent a partially implemented change doc carries no per-phase index annotation, and PRDs 40 and 41 stay `active`/`Current`.

Validation: full CLI suite 885/885 across 54 files this session with the build green, `npm run validate:defaults` exit 0 (no pinned heading-list update in `packages/cli/tests/consistency.test.ts` was needed — the register closures changed item bodies, not headings), `python3 .make-docs/scripts/check_path_hygiene.py` clean, relative links in the touched docs verified to resolve, no guide promoted past `draft`, no unresolved placeholders, and `git diff --check` clean for every doc this session touched.
