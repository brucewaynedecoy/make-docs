# W18 R10 P3 Unified Project-State Model and Evidence Migration

## Changes

Implemented W18 R10 Phase 3 of [PRD 38](../../../prd/38-revise-global-store-and-project-state.md) — the unified project-state model (R-PS-1 through R-PS-3), the checkpoint-to-evidence migration (R-PS-2/R-BND-2), and the registry-mirror behavior (R-MIR-1/R-MIR-2) — across `packages/cli/`. The new [`src/store/project-state.ts`](../../../../packages/cli/src/store/project-state.ts) is the model layer: `PROJECT_STATE_TABLE_ROLES` encodes the mirror-versus-relocated role of every table (registry rows are mirror data rebuildable from manifests; project-state rows are relocated-canonical with no in-repo copy), `WorkItemIdentity` is the canonical work-item identity tuple (resolved repo root, wave slug, phase path) accepted verbatim from the retained resolver, and `recordWorkEvidence`/`readWorkItemEvidence`/`listWaveEvidence` are the evidence seam. `src/store/state-rows.ts` adds the run-state facet seam the W18 R7 runner consumes — `createPlaybookRunRecord`, `readPlaybookRunRecord`, `transitionPlaybookRunRecord` (which can never silently create state), and `listPlaybookRunRecords`, keyed by project identifier plus run identifier with the record payload fully opaque so the W18 R7 lineage owns its shape and progression. Both facets stay on schema version 1 with one migration path — a recorded implementer decision in [the store module README](../../../../packages/cli/src/store/README.md), since the v1 layout already expresses both facets, so no v2 migration was warranted. The `checkpoint` operation in [`src/operations/lifecycle/index.ts`](../../../../packages/cli/src/operations/lifecycle/index.ts) now writes global-store work-execution evidence instead of `.make-docs/runs/<wave-slug>/state.json`, per the disposition-reviewed field mapping tabled in the store README: validation, review, closeout, commit, push, notes, and the wave-level commit policy are kept as evidence kinds, while phase status, resolver outputs (`waveSlug`/`waveDir`/`target`/`coordinate`/`mode`/`nextPhasePath`/`activePhasePath`), `phasePath` (which becomes the row key), and schema-version/timestamp bookkeeping are dropped as re-derivable. Legacy checkpoint files migrate lazily inside the mutating checkpoint operation — read the old file, write evidence rows only for kinds the store does not already hold so legacy data never overwrites recorded evidence, then delete the file and prune emptied `runs/` directories; the delete-after-migrate rule is a recorded implementer decision (PRD 38 and the inventory are silent) justified by R-MIR-2's no-in-repo-copy requirement. Read-only operations (`phase-gate`, `wave-status`) consult unmigrated files read-only with warnings, and the mutating checkpoint fails explicitly — never a repository fallback — on unresolvable identity or an unavailable store. The new [`src/store/registry-mirror.ts`](../../../../packages/cli/src/store/registry-mirror.ts) keeps the `projects` table strictly subordinate to manifests: `mirrorProjectManifest` is wired into `src/cli.ts` immediately after `bootstrapGlobalStore` (closing the P2 deferral), `readAuthoritativeInstallRecord` always resolves to the project's `.make-docs/manifest.json`, and `rebuildProjectRegistry` re-mirrors from manifests in one transaction without touching the relocated-canonical facets. Operation output shapes changed accordingly (no more `statePath`/`state`; now `evidence`, `evidenceSource`, `projectIdentity`, `legacyCheckpoint`, `warnings`, `droppedFields`). Tests landed as `packages/cli/tests/project-state.test.ts` (9 tests), rewritten checkpoint/gate/migration coverage in `tests/operations.test.ts`, and a mirror assertion in `tests/store.test.ts`; the full suite passes 32 files / 532 tests, the build succeeds, and all ten tasks in [the Phase 3 backlog file](../../../work/2026-07-01-w18-r10-global-store-and-project-state/03-unified-project-state-model-and-evidence-migration.md) are checked off. Boundary notes: the template runtime-state guidance still naming `.make-docs/runs/` is Phase 5's deliverable, the MCP tool descriptions naming `.make-docs/runs/playbooks/**` are W18 R7's relocation, and `tests/tool-directory.test.ts` correctly keeps classifying `.make-docs/runs/**` as runtime-state paths while unmigrated legacy files can exist.

Developer-guide coverage was `update-existing` because [the docs assets and runtime state boundaries guide](../../library/developer/maintainer-docs-assets-and-runtime-state-boundaries.md) already owns the state-boundary story its P2 Future Coverage bullet gated on P3: its Machine-Level Global Store boundary rules gained the code-encoded mirror-versus-relocated split with the never-trust-the-mirror and never-write-relocated-state-in-repo rules, the two-facet one-schema model with the opaque run-record seam and the never-re-derive-identity rule, and the checkpoint retirement — lazy migrate-and-delete with the never-overwrite rule, read-only degradation with warnings, explicit failure instead of repository fallback — routing to the store README's mapping table rather than restating it; the Future Coverage gate narrowed from Phases 3 and 4 to Phases 4 and 5 plus the W18 R7/R11 consumers. [The runner architecture guide](../../library/developer/playbooks-development-runner-architecture.md) kept its Run State rewrite gated on W18 R7, but its Future Coverage bullet was updated to state that the storage seam is now complete (P1 table plus P3 create/read/transition/list record seam) rather than implying only the P1 table existed. User-guide coverage was `none` for new content because no user guide documents the work-on-wave/checkpoint workflow today (verified by search: the only user-guide mention is the `work-on-wave` skill name in a selection table), so the changed operation output shapes and migration warnings have no owning user artifact and are agent/maintainer-facing surfaces; the one `update-existing` touch narrowed [the lifecycle guide](../../library/user/cli-lifecycle-managing-installations.md) Future Coverage gate from Phases 3 and 4 to Phase 4 plus W18 R11, since its gated content (store inspection, pruning, machine-footprint removal, privacy note) is P4/R11 scope and P3 landed nothing user-visible for it. PRD coverage was `risk-register-update` because the phase implemented existing PRD 38 requirements without changing the active requirement surface: in [the open questions and risk register](../../../prd/03-open-questions-and-risk-register.md), R-019's Decision cell records the P3 landing (both facets on schema v1, the live run-state seam for W18 R7, checkpoint writing store evidence with no repository fallback, the mirror upsert wired) with P4, P5, and the R-TEST-5 consumption still open and its Follow-Up retargeted to lifecycle next; R-023's Decision cell records that its three P3-open items closed — manifest-authoritative registry reads, demonstrated rebuild-from-manifests, and the disposition-reviewed field mapping recorded in the store README — plus the never-overwrite migration rule and the delete-after-migrate decision, and the item stays Open pending the P4 lifecycle assertions (R-TEST-4) and P5 verification per the register's status rules; numbers, headings, and statuses are unchanged, so the heading list pinned by `packages/cli/tests/consistency.test.ts` (which pins headings and table shape, not statuses) is unaffected. [The migrated-operations inventory](../../artifacts/migrated-operations-inventory.md) got a `none` verdict: it is pre-design evidence, not a contract, its open storage question was answered by PRD 38 and the resolution is now recorded in R-023 and the store README (both of which cite the inventory), and rewriting the artifact would rewrite history. Manual-test/UAT coverage is deferred until wave completion per user instruction; the natural UAT is running a checkpoint in a repo with a legacy `.make-docs/runs/<wave-slug>/state.json`, confirming evidence rows appear in the store, the legacy file is deleted, and a repeat checkpoint never overwrites the recorded evidence.

Validation: jdocmunch was reindexed over the docs tree, `check_path_hygiene.py` reports zero errors, every relative link added this session resolves, and `git diff --check` is clean. No template-owned files were touched (the template runtime-state guidance update is Phase 5's deliverable), the uncommitted W18 R10 P3 code changes under `packages/cli/` were left as-is for the orchestrator's combined commit, and the concurrent W18 R6 backlog files under `docs/work/2026-07-01-w18-r6-*` were left untouched.
