# Make Docs 2.0.5 release notes — draft

These notes cover the changes since 2.0.4. They are ready for release review. Version 2.0.5 is not published.

## MCP tools and resources

- Added the `core`, `setup`, `workflow`, `quality`, and `backlog` MCP profiles. `make-docs mcp` still serves the complete `all` profile over stdio. Use `make-docs mcp --profile <name>` to expose one smaller set. A profile limits discovery and calls; it does not grant access.
- Added profile-aware resource discovery and reads. A resource outside the selected profile stays unavailable to that connection.
- Gave MCP tools shorter, fixed names. Existing CLI commands and operation IDs stay the same. Saved MCP calls that use an old tool name must use the [name map](../../plans/2026-10-23-w26-r1-mcp-tool-names/01-name-contract.md). The old MCP names have no aliases.

## Store access

- Added one shared Store access check for MCP calls. The check uses the current connection key, machine grant, project grant, and requested operation. A changed or wrong key does not keep an earlier grant.
- Kept direct CLI operations on their local operator path. Generic setup returns client-owned connection text for review. First-party setup keeps its review and recovery steps.
- Added tests for grant changes, source versions, migration, rollback, and sandboxed MCP calls.

## GitHub Copilot and setup

- Added GitHub Copilot to the agent platform choice. It shares `AGENTS.md` and `.agents/` conventions with Codex. Selecting an MCP method configures only the selected harnesses.
- Added one managed GitHub Copilot CLI MCP entry. The GitHub Copilot app can use that CLI entry. Entries added in the app stay owned by the user.
- When project setup succeeds but a selected harness MCP entry needs manual setup, setup reports the project as ready and that harness as pending. The terminal prints the exact entry for the user to add. Machine-readable output does not include the raw key.
- Removed the repeated “Project state” text inside the first setup card.

## Security and package checks

- Updated the MCP SDK to 1.32.2. Updated the locked `proxy-addr` version to 2.0.8 and `source-map-js` to 1.2.2.
- Corrected HTML comment handling in the Cleanup Docs Skill. Corrected file-link encoding in the Backlog Review Skill.
- The [security review](2026-10-24-v2.0.5-security-review.md) records the remaining alert and release checks.

## Upgrade notes and limits

- Restart each MCP client after updating so it loads the current tool list. Update saved calls that use old MCP names.
- Run setup again to review GitHub Copilot selection and MCP entry changes. If a client policy blocks MCP, the user must resolve that policy outside Make Docs. Manual entry text does not bypass the policy.
- Direct Copilot CLI and app proof covers macOS. Windows and Linux contract checks passed in CI, but direct Copilot client runs on those hosts remain unproved. A same-name entry added through the app remains unproved.
- This release does not add an HTTP MCP listener. The supported live server path remains stdio.
