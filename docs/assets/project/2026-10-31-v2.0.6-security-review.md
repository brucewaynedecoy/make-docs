# Make Docs 2.0.6 security review

Date: 2026-10-31. This review covers the locked dependency tree, the tested 2.0.6 package, and open GitHub alerts on `main` at `4a77c26c2fc3cc74cc9326124434e40e3b252743`. The GitHub Release is still a draft.

## Dependency and package checks

- A fresh `npm audit --omit=dev --json` reported zero critical or high alerts and one moderate alert.
- A fresh `npm audit --json` reported zero critical or high alerts, one moderate alert, and one low alert.
- The moderate alert is [GHSA-rmxm-3fg6-px4f](https://github.com/advisories/GHSA-rmxm-3fg6-px4f) in transitive `@hono/node-server@1.19.17`. `@modelcontextprotocol/sdk@1.32.2` pulls it in. The issue affects `serveStatic` when a server protects static paths with middleware. Make Docs serves MCP through stdio and does not start that HTTP static server. This is an exposure assessment, not a claim that the dependency is fixed.
- The low alert is [GHSA-g7r4-m6w7-qqqr](https://github.com/advisories/GHSA-g7r4-m6w7-qqqr) in development dependency `esbuild`. It concerns the development server on Windows. The shipped CLI does not start that server.
- The package lock changed only the CLI workspace version. No dependency version changed. The final tarball has 141 entries, including the MIT license, README, CLI binary, and templates. Its SHA-256 is `9e1520c49167eb731e4bac506d8ee2cdb968382815888ddd5eb1b270058a5674`.
- [PR #55](https://github.com/brucewaynedecoy/make-docs/pull/55) passed the installed-package checks on Windows, Ubuntu, and macOS. Its package comparison and merge gate passed. Its CodeQL check reported no new alerts in the changed code; that result did not close older alerts on `main`.

## Open GitHub alerts

- [Dependabot](https://github.com/brucewaynedecoy/make-docs/security/dependabot) shows one open low alert: [esbuild #1](https://github.com/brucewaynedecoy/make-docs/security/dependabot/1). It is a transitive development dependency. The issue needs the esbuild development server on Windows. [PR #53](https://github.com/brucewaynedecoy/make-docs/pull/53) offers a patched version. The alert remains open.
- [Code scanning](https://github.com/brucewaynedecoy/make-docs/security/code-scanning) shows 36 open CodeQL alerts on `main`: eight high and 28 medium. All 28 medium alerts point to test files. The sampled details show code built for child-process test fixtures. These files do not run in the installed CLI.
- Three high alerts, [#32](https://github.com/brucewaynedecoy/make-docs/security/code-scanning/32), [#33](https://github.com/brucewaynedecoy/make-docs/security/code-scanning/33), and [#34](https://github.com/brucewaynedecoy/make-docs/security/code-scanning/34), point to links in the shipped Backlog Review report. The inspected code builds a `file://` URL and encodes path parts. It sets link labels with `textContent`. This review found no path that interprets those labels as HTML or changes the URL scheme. This code assessment does not replace a focused hostile-input test.
- High alert [#40](https://github.com/brucewaynedecoy/make-docs/security/code-scanning/40) points to a build script. Its regular expression reads a checked-in report template. It does not filter untrusted data in the installed CLI.
- High alerts [#41](https://github.com/brucewaynedecoy/make-docs/security/code-scanning/41) and [#42](https://github.com/brucewaynedecoy/make-docs/security/code-scanning/42) point to tests. High alerts [#39](https://github.com/brucewaynedecoy/make-docs/security/code-scanning/39) and [#43](https://github.com/brucewaynedecoy/make-docs/security/code-scanning/43) point to saved evidence under `docs/`. These paths do not run in the installed CLI.
- [Secret scanning](https://github.com/brucewaynedecoy/make-docs/security/secret-scanning) shows zero open alerts. [Malware alerts](https://github.com/brucewaynedecoy/make-docs/security/malware) are disabled, so that check gives no result.
- GitHub says it last checked dependency files on 2026-10-26. The Hono advisory was published on 2026-10-28. The fresh npm audit finds it, but GitHub does not show a matching open Dependabot alert.

## Release decision and follow-up

This review assesses the scope of the eight high CodeQL alerts. It found no confirmed security issue in the 2.0.6 candidate that requires a fix before release. The known alerts remain open. The security review recommends proceeding with 2.0.6 after the draft tag, target commit, notes, and package version receive their final release check. Publication is a separate user action.

After release, review the CodeQL findings with focused tests or fixes. Track the moderate Hono dependency alert and the low esbuild alert. Do not mark an alert fixed solely because this release accepted its risk.
